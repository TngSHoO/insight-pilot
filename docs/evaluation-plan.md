# 模型评测计划

## 评测目标

验证模型是否能稳定、准确地把用户反馈转换为产品洞察，而不是只评估语言是否流畅。

## 对照实验

| 版本 | 说明 |
|---|---|
| Baseline | Qwen3-4B简单提示词 |
| Prompt | 当前结构化提示词与证据约束 |
| LoRA + Prompt | 后续使用人工标注数据微调的版本 |

## 指标

1. JSON结构正确率：结果能被程序直接解析的比例。
2. 引用准确率：结论能否在引用反馈中找到依据。
3. 痛点召回率：人工标注痛点被模型覆盖的比例。
4. 优先级一致率：模型优先级与人工判断的一致程度。
5. 幻觉率：不存在于原始反馈中的事实占比。
6. 响应时间：固定20条反馈的端到端耗时。
7. 人工可用性：产品经理对结果的1—5分评价。

## 简历使用原则

评测完成前不填写虚构提升百分比。简历中的数据必须能在评测脚本、原始结果或报告中复现。
